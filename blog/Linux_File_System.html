📂 Understanding the Hierarchy

Unlike Windows, which uses physical drive letters (like C:), Linux utilises a logical, hierarchical tree structure starting from a single point known as the root (/).

Everything in a Linux system — files, directories, devices, and even running processes — is represented as a file within this unified namespace. This design, inherited from Unix, is one of the core philosophies that makes Linux powerful, flexible, and scriptable.

The Filesystem Hierarchy Standard (FHS) defines the structure and purpose of each major directory, ensuring consistency across all Linux distributions.

📋 Essential Directories Explained

These are the core directories you'll encounter on every standard Linux system. Understanding them is the first step to mastering Linux administration.

/Root — the top of the filesystem tree.
/binEssential user binaries — ls, cp, mv, cat.
/bootKernel and boot loader files (GRUB, initramfs).
/devDevice files — hardware interfaces (disks, terminals, printers).
/etcSystem configuration files — /etc/passwd, /etc/fstab.
/homeUser home directories — personal workspace for each user.
/libShared libraries and kernel modules — essential for binaries in /bin and /sbin.
/mntTemporary mount point for manual filesystem mounts.
/optOptional third-party software packages (self-contained).
/procVirtual process filesystem — runtime system information.
/rootHome directory for the root (superuser) account.
/sbinSystem administration binaries — fdisk, mount, mkfs.
/tmpTemporary files — cleared on system reboot.
/usrUser system resources — shareable, read-only data (binaries, libraries, docs).
/varVariable data — logs, caches, spool files, and temporary data.
/sysVirtual filesystem exposing kernel objects and device information.

🧩 Filesystem Hierarchy Standard (FHS)

The FHS is a collaborative standard that defines the structure and purpose of directories on Linux and Unix-like systems. It ensures consistency, making it easier for administrators and developers to know where to find or place files.

📁 /bin vs /usr/bin
/bin holds essential binaries needed for booting and recovery; /usr/bin holds non-essential user programs.
📁 /lib vs /usr/lib
/lib contains libraries for /bin and /sbin; /usr/lib holds libraries for user applications.
🔗 Symbolic Links
Modern distributions often symlink /bin → /usr/bin and /sbin → /usr/sbin for simplification.
📦 Package Management
The FHS ensures that package managers (apt, dnf, pacman) know exactly where to install files, avoiding conflicts.
🧵 Mount Points
Directories like /mnt and /media are reserved for mounting external filesystems (USB, CD-ROM, network shares).
📊 Virtual Filesystems
/proc, /sys, and /dev are virtual — they exist only in memory and expose kernel and device information.

🔐 File Types & Permissions

In Linux, everything is a file — but not all files are the same. The first character of a long listing (ls -l) reveals the file type.

- Regular file (text, binary, data)
d Directory — contains files and subdirectories
l Symbolic link — points to another file or directory
c Character device — serial ports, terminals
b Block device — hard disks, SSDs
s Socket — inter-process communication

Permissions are represented as rwxr-xr-- — three triples for owner, group, and others. r = read, w = write, x = execute.

💡 Quick Tip

Use chmod 755 script.sh to give the owner full permissions (rwx) and read+execute to everyone else. Never use chmod 777 on production systems!

🔢 Understanding Inodes

An inode (index node) is a data structure that stores metadata about a file — everything except its name and actual data. Each file on a Linux filesystem has a unique inode number.

Inodes store: file type, permissions, owner, group, size, timestamps (access, modify, change), and pointers to the data blocks on disk. The filename is stored only in the directory entry, which maps a name to an inode number.

COMMAND
ls -li
Shows inode numbers for files in a directory.
COMMAND
stat filename
Displays detailed inode metadata for a specific file.

🔑 Key insight: A hard link creates a new directory entry pointing to the same inode. Deleting the original file doesn't remove the data until all hard links are gone.

🧭 Absolute vs Relative Paths

Understanding path navigation is essential for moving through the filesystem efficiently.

Absolute Path
Starts from the / (root) and specifies the exact location.
/home/alice/Documents/report.txt
✅ Works from anywhere in the filesystem.
Relative Path
Starts from your current working directory (pwd).
./Documents/report.txt
🔹 . = current dir, .. = parent dir.
⚡ Quick Reference

~ = home directory  ·  / = root  ·  . = current directory  ·  .. = parent directory

⚡ Pro-tip

Always log in as a regular user for routine tasks. Only use root privileges when strictly necessary — it keeps your system secure and prevents accidental damage. Use sudo for individual commands that require elevated privileges.

sudo apt update sudo systemctl restart nginx sudo chown user:group file
